# 18 ADXL345 三轴加速度计（c6_adxl345，SPI 本地诊断传感器）

| 项 | 内容 |
|---|---|
| 代码位置 | `components/c6_adxl345/` |
| 上游需求 | 台架 bring-up 运维需求（无 LLDD 编号） |
| 状态 | 🟩 代码完成；IDF v6.1-beta1 编译通过（零告警）；真机读数待台架 |

## 1. 定位与数据通路

- **C6 本地诊断传感器**：读数只进 `/api/diag` 的 `"imu"` 字段，**不进 v2/SF
  线路协议**——运动安全裁决仍在 TC275，本模块只是台架/诊断仪表；
- 通路：采样任务（默认 20 ms）→ `portMUX` 临界区保护的快照 →
  `app_diag_render()` 追加 `"imu":{"ok":..,"mg":[x,y,z],"mag":..,"upd":..,"err":..}`；
- 芯片缺席时优雅降级：`start()` 探测失败只打一条 WARN，无任务、
  `"imu":null`，启动流程不受影响。

## 2. 硬件与驱动

- 模块：GY-291 风格 ADXL345 八脚模块（GND/VCC/CS/INT1/INT2/SDO/SDA/SCL），
  VCC 接 3V3（模块载 662K LDO），INT1/INT2 悬空；
- **位拍（bit-bang）4 线 SPI**：C6 唯一的通用 SPI 控制器（GPSPI/SPI2）已被
  LINK 从机占用（`spi_slave_hd`，18/19/20/23），硬件控制器无法再挂 SPI 主机，
  故用 GPIO 软件时钟。SPI **mode 3**（CPOL=1/CPHA=1，数据上升沿采样、
  下降沿换相），半位 1 µs ≈ 500 kHz（ADXL345 上限 5 MHz，诊断场景不需要）；
- 引脚映射（Kconfig 可改；避开 strapping 4/5/8/9/15、USB 12/13、
  UART0 16/17、LINK SPI 18-21/23、WS2812 8；**GPIO14 未引出到排针**）：

  | 模块脚 | C6 默认 | 角色 |
  |---|---|---|
  | CS | GPIO7 | 片选（推挽驱动；SPI 模式下必须由主机驱动） |
  | SCL | GPIO10 | SCLK |
  | SDA | GPIO11 | MOSI（SDI） |
  | SDO | GPIO6 | MISO（内部上拉使能） |

  四根信号线全部落在 DevKitC-1 的 J1 排针（6/7/10/11 相邻），接线集中；

- 寄存器时序：standby → `BW_RATE`（最近档位）→ `DATA_FORMAT`
  （FULL_RES + 量程）→ `POWER_CTL.Measure`；数据帧一次 6 字节从 `DATAX0`
  连读（MB=0x40，CS 全程拉低，帧间 CS 高 ≥5 µs）；
- 全分辨率模式标定 3.9 mg/LSB 恒定，整数运算（`raw*39/10`）换算毫 g，
  采样任务不碰软浮点；幅值 `mag = isqrt(x²+y²+z²)`（静止 ≈1000 mg）；
- **存活检查**：软件总线无协议级失败信号，每 250 个周期（≈5 s）回读
  DEVID(0xE5)，失配则 `ok=false`、`err++` 并限频告警；上电探测失败则
  不启动任务（DEVID 探测是芯片在位与接线的最终判据）。

## 3. 配置

| Kconfig | 默认 | 说明 |
|---|---|---|
| `C6_ADXL345_ENABLE` | y | 关闭后 `adxl345_*` 变空实现（c6_led 同款 stub 模式），调用点零条件编译 |
| `C6_ADXL345_SCLK/MOSI/MISO/CS_GPIO` | 10/11/6/7 | 位拍总线四脚（均在 J1 排针） |
| `C6_ADXL345_HALF_BIT_US` | 1 | 半位时长，1 µs ≈ 500 kHz |
| `C6_ADXL345_RANGE_G` | 16 | 全分辨率下只决定削顶；2/4/8/16 取最近档 |
| `C6_ADXL345_ODR_HZ` | 100 | BW_RATE 就近档位（12.5–1600） |
| `C6_ADXL345_POLL_MS` | 20 | 采样周期（50 Hz） |

- **IDF v6.1-beta1 目标机编译通过**（macOS EIM 环境，riscv32-esp-elf/gcc 15.2，
  `-Werror` 下零告警）：`esp32c6_car.bin` 0x10CC70，app 分区余 65%；
  Kconfig 新符号全部落入 `build/config/sdkconfig.h`；
- host gcc `-fsyntax-only -Wall -Wextra`：ENABLE=y / =n 双配置通过（stub
  分支同验，零告警）；
- host 链接级（stub 外设）：`app_diag_render` 实跑——`imu:null` 降级路径与
  运行态 `{"ok":true,"mg":[12,-34,987],"mag":988,...}` 均输出合法 JSON
  （python `json.loads` 校验）；32 B 截断缓冲下 ASan/UBSan 无越界；
- **v6.1 移植注意**：C6 的 `gpio_dev_t` 寄存器是类型化联合体
  （`gpio_out_w1ts_reg_t` 等），老靶机直接赋整数的裸寄存器写法**编译不过**，
  位拍翻转统一走 `gpio_set_level()/gpio_get_level()`（与 c6_link IRQ 线同款，
  500 kHz 软时钟下开销可忽略）；
- **真机（macOS 侧烧录，2026-09-28）**：四件套烧录成功、ota_0 启动正常；
  未接线时 DEVID 探测读到 0xf2 → 一条 WARN 后不启动采样任务、boot 继续
  （`"imu":null` 降级路径真机验证通过）；接线后读数待验证；
- 待办：台架接线（7/10/11/6 + 3V3/GND）后 `/api/diag` 读数与 1g 静止幅值校验；
- 后续可选：OFSX/Y/Z（0x1E–0x20，15.6 mg/LSB）零偏标定、INT1 运动中断。
